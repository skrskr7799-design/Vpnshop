# MZT V5 — матрица реализации

База ветки при начале разработки: `fbf516b`, V2.0.1: `8849e84`. Накопительные требования импортированы без редактирования. Правила принятия решений — разделы 8–9 и START-HERE из handoff. Исходный CSS и геометрия служат визуальным эталоном. JS приложения-прототипа и его данные остаются демонстрационными.

## Порядок

1. Прогресс и авторизация обновления CLI.
2. Общая геометрия срезов, библиотека иконок, статический V5 и подтверждённый переход входа. Сохранить действующий охват браузерных smoke.
3. Кабинет с реальными проекциями и состояниями. Checkout и доступ к ссылке остаются под серверными политиками.
4. Поиск, карточка и операционные разделы админки. Добавлять команды через существующий протокол.
5. Контракты интеграций, проверки PostgreSQL, обновление, визуальная приёмка и ограничения.

### Серверная политика ссылок и происхождение OAuth

- **ACC-02**. Общая политика хранится в существующих настройках магазина. Переопределение аккаунта имеет приоритет. Значение по умолчанию сохраняет доступ до настройки. Обе административные команды используют разрешения, обязательный step-up, проверку версии и аудит. Запрет применяется к выдаче URL через API магазина, включая копирование и QR, и перепроверяется после чтения панели. Уже полученная копия регулируется панелью. Выдача VPN и оплаченные права от этой настройки не меняются.
- **AUTH-36**. Метод подтверждённой авторизации записывается в ту же транзакцию, что и пользовательская сессия. `/auth/me` получает его из живой семьи сессии. Вход, начатый до миграции, возвращает неизвестный метод. URL служит только сигналом для визуального перехода и не может установить метод без подтверждения API.
- **UX-04**. Для API на публичном Edge и шлюзе отключён proxy cache. Регрессия проверяет заголовок и изоляцию последовательных ответов в режиме private и mTLS. Приложение уже выставляет `private, no-store` для сессий, подписки и ссылки.
- Миграция `20261128000100_verified_entry_and_link_policy` добавляет столбцы без backfill. CI содержит отдельную проверку обновления с V2.0.1 и сохранения сессии, внешнего ID и операторских настроек. До релиза нельзя объявлять совместимость отката на версию, обходящую запрет выдачи ссылок.

### Зарегистрированные устройства Remnawave

- **ACC-04**. Кабинет читает число и список регистраций HWID из `GET /api/hwid/devices/:userId` в официальном контракте Remnawave 3.4.9. Перед чтением проверяется подтверждённая привязка и профиль, после чтения — актуальность привязки, права и сессии. В ответ магазина входят тип, модель и даты записи. HWID, IP и строка User-Agent остаются внутри интеграции. Количество регистраций отличается от числа активных туннелей.
- **ACC-03 / ADM-04**. Сверены оригинальные контракты чтения и перевыпуска. Операции записи пока открыты. Для ротации требуется стендовая проверка старой ссылки и поведения при потерянном ответе. Поддерживаемый внешний ключ идемпотентности для этой команды не подтверждён.

### Карточка клиента и индексы поиска

- **ADM-02/03/05/06/07/09**. Профиль, подписка и история сгруппированы в карточке клиента. Тариф текущего периода, срок и лимит получены из существующей проекции оплаченных прав. История сессий и отзыв всех сессий доступны OWNER/ADMIN. Команда использует действующее отзывное хранилище, step-up, версию объекта, идемпотентность и аудит. Финансовые сведения по-прежнему открываются через отдельные заказ и финансовые права.
- **ADM-01**. Для точного имени и платёжных реквизитов добавлены индексы. Миграция `20261128000200_staff_customer_lookup_indexes` входит в проверку обновления с V2.0.1. Точные условия совпадения, приоритет RBAC и предельный размер выдачи сохранены.
- Не включены объединение и удаление клиентов, смена проверенного email, перенос подписки, новые финансовые команды и выгрузка персональных данных.
