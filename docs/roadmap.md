# Дорожная карта Vpnshop

**Цель ядра** — покупатель оплачивает и продлевает VPN, а сотрудник может объяснить результат каждого платежа и восстановить выдачу через админку. Этап визуального дизайна открывается после приёмки всего ядра. До этого покупатель и оператор работают через простые функциональные экраны.

Границы модулей, правила учёта и взаимодействие с Remnawave закреплены в [архитектуре](architecture.md). Галочку в карте ставим по результату соответствующей проверки. Для стендовой приёмки рядом с пунктом указываем коммит, сценарий и результат без секретов и ссылок подписки.

## 1. Воспроизводимый запуск и надёжная очередь

- [x] Устранить блокировку выдачи другим покупателям за длинной очередью одного клиента. Запрос захвата проверен на PostgreSQL 17 с 30 ожидающими продлениями и отдельным готовым заказом. Регрессионный сценарий добавлен в [набор интеграционных тестов](../apps/api/src/modules/fulfillment/fulfillment.int.test.ts).
- [ ] Добиться повторяемого запуска CI на чистой машине. Проверки включают установку по lockfile, генерацию Prisma Client, проверку типов, сборку, модульные тесты и интеграционные тесты на отдельном PostgreSQL. В облачной среде получение движков Prisma пока блокирует HTTP 403.
- [ ] Ввести версионированные миграции и безопасную подготовку тестовой БД. Проверить создание базы с нуля и обновление копии существующей базы с сохранением пользователей, платежей и сроков.
- [ ] Выделить запуск воркера и фиксировать владельца попытки выдачи. Проверить повтор после падения между записью в панель и фиксацией в БД, конкуренцию двух попыток и порядок продлений одного пользователя.

## 2. Первая покупка и продление

- [ ] Через admin API создать тариф и цену. В публичном каталоге показать только активные предложения. При заказе сервер сохраняет срок, лимит, валюту и сумму. Повтор оформления с тем же ключом возвращает тот же заказ.
- [ ] Подключить один согласованный платёжный канал. Подтверждение провайдера, переход заказа в оплаченный статус и постановка задачи выдачи фиксируются согласованно. Проверить дубликат подтверждения, неверную сумму, истёкший заказ и потерю ответа при создании счёта.
- [ ] В кабинете показать тарифы, кнопку оплаты, историю заказов, состояние доступа, срок и ссылку владельца. На стенде пройти путь от оформления до подключения тестовым VPN-клиентом. Проверить срок и лимит устройств в Remnawave.
- [ ] Продлить действующую и истёкшую подписку. Два отдельных оплаченных заказа дают два периода. Повтор обработки одного заказа сохраняет срок. Ручная блокировка в панели видна клиенту и сотруднику.

## 3. Функциональная админка

| Кто | Что должно выполняться через интерфейс |
|---|---|
| ADMIN и SUPPORT | Войти через пароль и TOTP, выйти, найти пользователя или заказ, посмотреть платёж, срок, состояние панели и понятную причину задержки. |
| SUPPORT | Просмотреть тарифы и очередь в рамках своих прав. Изменение цен, повторная выдача и денежные операции отклоняются сервером. |
| ADMIN | Создать и отключить тариф, изменить цену для новых заказов, проверить снимок условий старого заказа, вернуть упавшую задачу в очередь после исправления причины. |
| ADMIN при спорной оплате | Найти обе попытки платежа, зафиксировать решение о возврате или ином урегулировании и проверить его влияние на последующие продления. Операция отражается в журнале. |

- [ ] Подключить admin UI к закрытому admin API и выполнить сценарии таблицы в браузере под обеими ролями. Проверить серверные ограничения и отзыв сессии.
- [ ] На одном оплаченном, задержанном заказе показать, что поддержка устанавливает причину, администратор восстанавливает выдачу, клиент получает доступ, а повтор операции сохраняет оплаченный срок. По журналу устанавливаются автор, заказ и результат.

## 4. Приёмка ядра на стенде

- [ ] Временная недоступность Remnawave оставляет платёж учтённым. После восстановления воркер завершает выдачу. Пропущенное уведомление о платеже восстанавливается сверкой с провайдером.
- [ ] Оператор получает уведомление о задержанной выдаче. По номеру заказа находит платёж и задачу, различает ошибку провайдера и ошибку панели и видит время последней сверки.
- [ ] Восстановить PostgreSQL из резервной копии в отдельной среде, сверить деньги и сроки с внешними системами, проверить возобновление выдачи без повторного начисления.
- [ ] На одном релизном коммите пройти CI, покупку, подключение, продление и сценарии обеих ролей админки. Для ошибок, ведущих к утрате денег, доступа или истории операций, обязательны исправление и повторная проверка.
