## Доказательства кандидата

- Toolchain CI на ветке REL выполняет locked install, проверку и генерацию Prisma, lint, typecheck, сборку, unit/contract, чистые и legacy-миграции, PostgreSQL suite, браузер и визуальный отчёт. release-journey.int.test.ts связывает два контура HTTP и PostgreSQL. Процессы провайдера и панели остаются fixtures. [Workflow на ветке REL](https://github.com/skrskr7799-design/Vpnshop/actions?query=branch%3Awork%2Frel-01-02-release-acceptance) · [E2E](../apps/api/src/test/release-journey.int.test.ts)
- Infrastructure verification собирает семь образов, проверяет оригинальные runtime-роли и реальные TLS origins в одноразовом Compose. Репетиция останавливает PostgreSQL и возвращает его, проверяет liveness/readiness, завершает и заново запускает worker, проверяет отложенную запись outbox при отказе SMTP. Старый application runtime загружается из принятого исходника UX и запускается на той же схеме. Контрольные итоги сравниваются до и после, затем возвращается текущий образ. [Smoke](../ops/scripts/smoke.sh)
- PITR использует PostgreSQL 17, зашифрованный pgBackRest full/diff, синтетический S3 по TLS, WAL после снимка, значимый UTC target, сверку миграций, финансов и истории, инвалидирование старых сессий и повтор записей. Контейнер восстановления изолирован. Внешняя сверка провайдера остаётся обязательным отдельным этапом. [Drill](../ops/scripts/pitr.sh)
- Изолированный артефакт хранит проверяемый OCI архив и SHA-256 для архива и candidate.json. Manifest включает исходный SHA, хэши lockfile и каждой миграции, Node, pnpm, Prisma schema, параметры gates, platform и manifest/config digest каждого образа. Digest конфигурации предыдущего runtime фиксируется отдельно. Загруженный архив сопоставляется с теми образами, на которых выполнен Compose smoke. [Проверка OCI](../ops/scripts/release-manifest.py)
- Сканирование Git, npm и OCI использует read-only runner scope. SPDX и отчёты указывают образы кандидата. В публичный артефакт попадают только обезличенные результаты, без секрета или фрагмента с найденным значением. Публикация в registry проходит отдельный защищённый job. [Сканирование](../ops/scripts/scan-release.sh) · [Публикация](../.github/workflows/release-images.yml)

## REL-01 · Проверка CRITICAL в PostgreSQL и backup

Статус **BLOCKED**. Исходный кандидат `db50e84b54878838ef3a7876d25e1e2d2afb77a1` содержит три разные CRITICAL в каждом из образов `db` и `backup`. Trivy не показывает исправленных версий для установленной ветки Bookworm. Индексы amd64 для Bookworm, Bookworm Security и Bookworm Backports не предложили замену этим трём пакетам. [Отчёт Trivy и SPDX исходного кандидата](https://github.com/skrskr7799-design/Vpnshop/actions/runs/45038878894/artifacts/14761500129) · [Bookworm](https://deb.debian.org/debian/dists/bookworm/main/binary-amd64/) · [Bookworm Security](https://deb.debian.org/debian-security/dists/bookworm-security/main/binary-amd64/) · [Bookworm Backports](https://deb.debian.org/debian/dists/bookworm-backports/main/binary-amd64/)

| CVE | Пакет и установленная версия | Исправление | Применимость |
|---|---|---|---|
| CVE-2023-45853 | `zlib1g 1:1.2.13.dfsg-1` | В Bookworm отсутствует в данных Trivy, статус `will_not_fix`. Upstream исправил MiniZip после zlib 1.3. | Уязвимый код относится к MiniZip. В обоих образах отсутствует установленный Debian-пакет `libminizip`. Отдельный путь исполнения MiniZip не подтверждён. Запись Trivy остаётся в gate. [CVE](https://www.cve.org/CVERecord?id=CVE-2026-6653) · [pgBackRest 2.57.0](https://github.com/pgbackrest/pgbackrest/blob/release/2.57.0/src/storage/s3/storage.c) |

Официальный `17.12-bookworm` уже соответствует закреплённому `sha256:837bed18782820fe967067cb5328b02b0d9992c1be9a37ee0c9c492cfc03af3b`. В официальном `17.12-trixie` (`sha256:223efeb196329b55b3b9a13db144956411dbc18e727e59f681c3e0aede6475cf`) Trivy сохраняет CVE-2026-6653 в Debian-сборке libxml2 на исходниках 2.9.14. Скан официального `17.12-alpine3.24` (`sha256:f9cf3e1f0066f0eb0c48707d864f0ac5941e9ff454a072077d97a4d278d07d73`) проверял базовый образ. На одноразовых кластерах PostgreSQL 17.12 одинаковый `en_US.utf8` показал версию collation `2.36` на glibc и отсутствие версии на musl. Официальный Alpine также использует UID PostgreSQL 70, текущий образ использует 999. Переход потребует отдельной проверки collation, индексов, совместимости PGDATA, прежних резервных копий и сборки pgBackRest под musl. [Метаданные официальных образов](https://github.com/docker-library/official-images/blob/master/library/postgres)

Изменения Dockerfile, pgBackRest, схемы и scan gate в этот проход отсутствуют. У исходного кандидата в `db` и `backup` соответственно 114 и 131 HIGH совпадений по пакетам, среди них преобладает Kerberos и остаются libxml2 и SQLite. Отчёты Trivy для исходных образов не указывают доступных исправлений для этих HIGH. До приёмки нужен поддерживаемый пакетный фикс или отдельно проверенный перенос на исправленную базу с сохранением backup и rollback. Статусы итогового SHA и новый манифест публикуются в GitHub Actions. [Проверки ветки REL](https://github.com/skrskr7799-design/Vpnshop/actions?query=branch%3Awork%2Frel-01-02-release-acceptance)

### Оценка остаточного риска

| CVE | Условие эксплуатации и граница доверия | Компенсирующие меры и остаток |
|---|---|---|
| CVE-2023-45853 | Уязвимость относится к записи ZIP через MiniZip при данных, контролируемых внешним субъектом. PostgreSQL и pgBackRest применяют системный zlib для сжатия. MiniZip не установлен отдельным пакетом, в штатных операциях магазина путь через его ZIP API не найден. | В PostgreSQL и backup нет публичного интерфейса загрузки архивов. Остаточный риск связан с возможной встроенной копией MiniZip или новым потребителем архива. Статус CRITICAL остаётся в отчёте. |
| CVE-2025-7458 | Эксплуатация требует передачи произвольных SQLite SQL-инструкций уязвимому процессу. GnuPG использует библиотеку локально для операций backup. PostgreSQL SQL и SQLite SQL обслуживаются разными движками. | Backup запускается от отдельного UID, с закрытым временным каталогом и ограниченными реквизитами. Остаток — компрометация контейнера, его рабочих файлов или новый путь подачи SQLite SQL. |
| CVE-2026-6653 | Ошибка use-after-free затрагивает разбор недоверенного XML с некорректной обработкой сущностей. Эта граница включает скомпрометированный endpoint или доверенную TLS-инфраструктуру. Эксплуатация конкретной сборки не доказана. | БД закрыта от публичной сети, штатные операции используют ограниченные роли, S3 использует закреплённый HTTPS endpoint и проверку TLS. Защитные меры ограничивают источники XML. Сбой процессов БД или архивации может нарушить доступность и целевой RPO. Этот остаток блокирует эксплуатационный допуск до совместимого исправления и повторного PITR. |

### Срабатывания проверки секретов в migrator

В отчёте для `92228700abdfe2d30fd809528ee5bccab891e8fb` два срабатывания. Исторический артефакт сохраняет только сумму, поэтому по нему классификация невозможна. Повторное сканирование выводит имя сканера, ID правила, путь или область метаданных образа и строку. Значения и фрагменты найденного содержимого остаются во временном каталоге runner. При реальном секрете подготовка интеграции останавливается до отзыва, ротации и проверки производных артефактов.
