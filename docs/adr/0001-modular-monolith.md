# ADR 0001 · Модульный монолит и отдельный процесс выдачи

**Статус — предложено, фаза 2.**

## Контекст

В репозитории уже есть общие схемы TypeScript, два Fastify listener, Prisma и PostgreSQL. Создание заказа, зачёт платежа и возникновение права требуют одной атомарной границы. Сетевые операции панели могут занимать дольше времени обычного HTTP-запроса. Сейчас worker запускается вместе с сервером при включённом WORKER_ENABLED. [Запуск](../../apps/api/src/server.ts#L8) · [Аудит](../audit.md)

## Решение

Один репозиторий и согласованная версия поставки. Разделить публичный API, закрытый административный вход и жизненный цикл исполнителя. Прикладные команды принадлежат конкретному модулю, общий координатор передаёт контекст транзакции. Внешние вызовы ограничены адаптерами. У worker собственные настройки, сигнал готовности, heartbeat, время корректного завершения и лимит одновременных внешних запросов. Для очереди использовать PostgreSQL.

## Основание и последствия

Совместный запуск API и worker проще для локальной разработки, но число исполнителей зависит от числа реплик API. Отдельный процесс убирает эту связь и оставляет одну транзакцию для денег и права. Раздельные хранилища и сетевой обмен между всеми модулями потребовали бы собственного механизма согласования. Их эксплуатационная выгода для имеющейся нагрузки не продемонстрирована.

Цена решения — дисциплина импортов, мониторинг одной БД, тесты миграций и измерение времени блокировок. Перед изменением топологии собрать p95/p99 задержки выдачи, возраст готовой задачи, время транзакций, насыщение пула и план выборки. Пересмотр нужен, если нагрузочный тест или требования изоляции показывают конкретный предел. [Модули и интерфейсы](../architecture.md)
