# ADR 0004. Подтверждённые административные команды

## Решение

Персонал использует выделенный User с StaffCredential и отдельным AdminSession. Password stage выдаёт opaque challenge с версией credential. Свежий пароль и TOTP выдают одноразовое подтверждение для конкретных операции, разрешения, цели, версии, причины и нормализованного payload.

Admin API использует одну короткую транзакцию PostgreSQL для изменения, использования подтверждения, записи результата и append-only аудита. Общий advisory lock упорядочивает административные записи, отзыв сессий и изменения персонала. Внутри него доменные блокировки сохраняют порядок каталога, подписок и выдачи. HTTP провайдеров выполняется вне транзакции. Точный повтор команды читает результат с проверкой действующего разрешения.

Намерение возврата резервирует средства конкретного подтверждённого CAPTURE в исходной валюте. Независимый ADMIN может одобрить резерв. Внешняя отправка требует проверенного контракта провайдера и отдельного допуска. Одобрение не создаёт денежное движение.

## Последствия

Внутренние команды сериализованы на время локальных записей. Обычные чтения и checkout сохраняют собственную конкурентность. Решение подходит для нагрузки одного административного контура. При измеримой нагрузке пересмотреть гранулярность по времени ожидания блокировок.

Старые staff cookies отзываются. Смешанные исторические аккаунты проверяются вручную. Компенсация использует самостоятельный интервал и ссылку на оплаченный период.
